# Operator Rules — YCLIENTS

## Запреты по умолчанию

- Не выполнять write-операции без явной команды владельца.
- Не создавать абонемент, если отсутствие эквивалентной карточки во всей истории не доказано.
- Не пополнять существующую карточку вместо выдачи новой, если владелец явно не запросил изменение баланса.
- Не превращать команды «прибавь/уменьши/спиши» в посещения.
- Не изменять все похожие карточки при неоднозначности.
- Не выводить токены, ключи, cookies, OAuth-файлы и полные клиентские выгрузки в логи или чат.

## Identity

1. Нормализовать email в lowercase.
2. Нормализовать телефон до единого цифрового формата.
3. Telegram сравнивать exact, без wildcard/fuzzy matching.
4. Любой конфликт client ID, email, телефона или Telegram блокирует операцию.
5. Перед записью повторно проверить exact ownership выбранной карточки.

## Выдача абонемента

1. Собрать immutable source allowlist.
2. Проверить полную историю эквивалентных карточек всех статусов.
3. Разрешать только `issue_new`, если новая выдача явно запрошена.
4. Перед mutation сохранить intent-ledger.
5. После выдачи проверить новую card ID, balance, expiration и status.
6. Проверить transaction: exact client ID, good ID, document ID.
7. Выполнить независимый live reread.
8. Повторить тот же запуск и потребовать `0 writes`.

## Коррекция баланса

1. Выбрать ровно одну конкретную карточку.
2. Сохранить `before`, точный `target`, card ID и неизменяемый expiry.
3. При timeout/неоднозначном ответе сначала перечитать live state; не повторять mutation вслепую.
4. После записи подтвердить `after == target` и неизменённый expiry.
5. Идемпотентность строить по исходному `before` и completion marker, а не по новому `live + delta`.

## Ошибки и rate limits

- `429`, timeout и retryable `5xx`: небольшой capped backoff, затем полный reread.
- Массовые history/card audits запускать последовательно или с низкой concurrency.
- Если один fragment не получен, весь manifest считается неполным и execute блокируется.
- Transport 403 и logical 403 диагностировать отдельно.

## Аналитика

- Посещения брать из фактической истории визитов, не выводить их из текущего баланса.
- Ручные изменения баланса учитывать отдельно от посещений.
- Окна дат всегда документировать как inclusive/exclusive.
- Персональные исключения хранить в приватной deployment-конфигурации, не в Git.

## Secrets

- Только отдельные отзываемые credentials оператора.
- Secret-файлы — вне Git, permissions `0600`.
- SSH private key генерируется и хранится на устройстве программиста.
- Не копировать `~/.hermes/.env`, `auth.json`, `state.db` или пользовательские сессии.
