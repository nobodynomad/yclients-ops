# Security and access model

## Сервер

Рекомендуется отдельный Unix-пользователь без членства в `sudo`. Программист сам генерирует Ed25519 keypair и передаёт владельцу сервера только публичный `.pub`-ключ. Существующий серверный приватный ключ никогда не копируется.

## Сервисы

Для программиста выпускаются отдельные отзываемые credentials:

- FF sales API: read-only, если поддерживается;
- YCLIENTS analytics: минимальный read-only scope;
- YCLIENTS mutations: отдельный доступ только при необходимости;
- Google Sheets: отдельный OAuth principal с доступом только к нужной таблице;
- модель/Hermes: собственная авторизация программиста.

## Хранение

Secret-файлы находятся в `secrets/`, принадлежат Unix-пользователю оператора и имеют permissions `0600`. Каталог имеет `0700`. `secrets/` и `runtime/` исключены из Git.

## PII

Реальные выгрузки и ledger не передаются через Git. Доступ предоставляется только к необходимым данным, с журналированием действий. Для разработки используются обезличенные fixtures.

## Отзыв доступа

1. Удалить публичный ключ из `authorized_keys` или заблокировать отдельного Unix-пользователя.
2. Отозвать его YCLIENTS/FF/Google credentials.
3. Завершить активные сессии.
4. Проверить audit/ledger.

Удаление SSH-ключа не заменяет отзыв API-токенов, и наоборот.
